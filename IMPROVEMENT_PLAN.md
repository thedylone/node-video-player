# Improvement plan

A prioritized list of fixes and improvements for this repo, written to be picked up and implemented across sessions.

## How to use this file

- Work top to bottom. Phase 1 items are bugs; do them before refactoring.
- Each item has an ID (e.g. `P1-03`). Use it in commit messages and branch names.
- When an item is done, tick its checkbox and add a short note (commit hash, or anything that changed from the plan). If an item turns out to be wrong or unnecessary, strike it through and say why rather than deleting it.
- Line numbers were recorded at commit `89e09df` and will drift. Functions and routes are named so you can find them again by searching.
- Findings came from reading the code; confirm each bug before fixing it. Use `npm ci` (not `npm install`) to install without changing `package-lock.json`. To run the server outside Vite until P1-07 is fixed, bundle it: `npx esbuild src/server/index.ts --bundle --platform=node --format=esm --packages=external --outfile=<scratch>/server.mjs`, then run it from a folder that has `node_modules` available.
- Keep changes small and in the style of the surrounding code (4-space indent, double quotes, `process.stderr.write` for logging until P3-04 replaces it).

## Project overview

- Vite + React 18 + React Router 6 client in `src/`.
- Express server in [src/server/index.ts](src/server/index.ts), mounted into the Vite dev server by [express-plugin.ts](express-plugin.ts) via `ssrLoadModule` (sets `process.env.VITE`). Outside Vite it serves `dist/` and calls `app.listen`.
- Database is a JSON file (`DB_FILE`, default `db.json`) holding `{ [id]: Video }` (see [src/server/schema.ts](src/server/schema.ts)). It is held in memory and rewritten by `updateDatabase()` every 60 s.
- Videos live in `DIRECTORY/<source>/<title>/*.mp4`. Thumbnails are generated by ffmpeg as `tn.png` in the title folder.
- Config comes from `.env`: `FFMPEG_PATH`, `FFPROBE_PATH`, `DB_FILE`, `DIRECTORY`, `PORT`.

## Phase 1 — Bugs

### Server: [src/server/index.ts](src/server/index.ts)

- [x] **P1-01 Crash on first run with no `db.json`.**
  `jsonfile.readFileSync(DB_FILE)` (line ~29) throws if the file is missing.
  *Fix:* if the file doesn't exist, start with `{}`. Also fix the defaults `"/db.json"` and `"/videos"` (lines ~13-14), which point at the filesystem root; use `"db.json"` and `"videos"`.
  *Done when:* deleting `db.json` and starting the server works and creates the file on the first save.
  *Status:* done on branch `fix/p1-01-missing-db` (not yet committed). Added `loadDatabase()`, which returns `{}` when `DB_FILE` is missing; a corrupt file still throws on purpose, so user data is never overwritten. Verified: with no `db.json` the server starts and writes it after the first scan, and a second start loads it.

- [ ] **P1-02 Uptime ticker crashes when stdout is not a TTY.**
  `start()` calls `process.stdout.clearLine` / `cursorTo` every second (lines ~448-457). These are undefined when output is piped (pm2, Docker, `> log.txt`), so the interval throws repeatedly. *Confirmed* while testing P1-01: running with output piped crashes about 1 s after start with a `clearLine` TypeError.
  *Fix:* only run the ticker when `process.stdout.isTTY` is true, or remove it.
  *Done when:* `node dist/server/index.js > out.log` runs without errors.

- [ ] **P1-03 A stray file in `DIRECTORY` crashes the scan.**
  In `addDirToDatabase`, every entry from `fsp.readdir(DIRECTORY)` is treated as a source folder. A file like `.DS_Store` makes the nested `readdir` fail with `ENOTDIR`. `updateDatabase()` is called without `await`/`.catch` in `start()` and `setInterval`, so the rejection is unhandled and kills the process.
  *Fix:* use `withFileTypes` and skip non-directories at the source level, as is already done for titles. Wrap `updateDatabase` so errors are logged, not thrown. Also handle `jsonfile.writeFile` rejecting.
  *Done when:* putting a file directly inside `videos/` causes no error, and a forced write failure is logged without crashing the server.

- [ ] **P1-04 New videos in an existing title folder never show up.**
  In `addDirToDatabase`, `vids` is only set when a title is first added (`if (current.includes(...)) continue;`).
  *Fix:* on each scan, update `vids` for existing entries too, preserving `counter` and `tags`. Sort `vids` so the order is stable.
  *Done when:* adding `b.mp4` to an existing title shows it in the watch sidebar after the next scan.

- [ ] **P1-05 Missing input validation lets bad data break search.**
  - `POST /api/tag` with no `tag` pushes `undefined` into `tags`. It is saved as `null`, and `getVideos` then throws on `x.toLowerCase()` for every request to `/api/videos`.
  - `POST /api/tags` accepts any type for `tags`.
  - `POST /api/count` with a non-numeric `num` stores `NaN` (which JSON-serializes to `null`).
  *Fix:* validate bodies. Require `tag` to be a non-empty trimmed string (but see P1-14 on how the client creates empty tags first), `tags` to be `string[]`, and `num` to be a finite integer. Return 400 otherwise. As a guard, make `getVideos` ignore non-string tags.
  *Done when:* `curl -X POST /api/tag -d '{"id":"<id>"}'` returns 400 and search keeps working.

- [ ] **P1-06 Production fallback route sends the file path as text.**
  `app.get("/*", (_, res) => res.send(frontendFiles + "/index.html"))` (line ~466) sends the path string, not the page.
  *Fix:* `res.sendFile(path.join(frontendFiles, "index.html"))`. Also give `app.listen` a default port (e.g. `Number(process.env.PORT) || 3000`) and log the URL.
  *Done when:* after `npm run build`, running the server and loading `/watch?id=...` directly renders the app.

- [ ] **P1-07 `build:server` likely produces a server that can't start.**
  The script compiles to CommonJS (`--module commonjs`), but `nanoid@5` only supports ES modules, so `require("nanoid")` fails. The project already has `"type": "module"`.
  *Fix:* build the server as ES modules (separate `tsconfig.server.json` with `module: NodeNext`, or bundle with esbuild/`vite build --ssr`), or run it with `tsx`. Add a `start` script.
  *Done when:* `npm run build && npm run build:server && npm start` serves the app.

- [ ] **P1-08 Edge cases in `/api/stream/:id`.**
  - `?index` is not checked. An out-of-range or non-numeric value builds a path ending in `/undefined`.
  - A suffix range like `bytes=-500` gives `start = NaN`.
  - `end` is not capped at `fileSize - 1`, and there's no `416 Range Not Satisfiable`.
  - `fs.statSync` blocks the event loop.
  - `Content-Type` is always `video/mp4`.
  *Fix:* validate `index` (400 if bad); parse ranges properly, including suffix ranges; cap `end`; return 416 for unsatisfiable ranges; use `fsp.stat`; derive MIME type from the extension. Also handle `stream.on("error")`.
  *Done when:* `curl -H "Range: bytes=-500"` returns 206 with the last 500 bytes and `?index=99` returns 400/404.

- [ ] **P1-09 Tag and count changes can be lost.**
  Changes only reach disk when the 60-second `updateDatabase` runs; a crash or restart loses them. Writes are not atomic, so a crash mid-write can corrupt `db.json`.
  *Fix:* add a `saveDatabase()` (debounced is fine) called after each change in `addCount`, `updateTags` and `deleteTitle`. Write to `db.json.tmp` and then `rename`.
  *Done when:* changing a tag and immediately restarting the server keeps the tag.

- [ ] **P1-10 Dev plugin problems: [express-plugin.ts](express-plugin.ts).**
  - The server module calls `start()` when it loads. Each time Vite reloads the module after an edit, a new set of `setInterval`s is created on top of the old ones.
  - The `catch` only logs and never calls `next(err)`, so failed requests hang.
  - The plugin has no types (`server` is implicitly `any`).
  *Fix:* export `start` and let the plugin call it once (or guard with a flag stored on `globalThis` and clear old intervals). Call `next(err)` in the `catch`. Type the plugin as Vite's `Plugin`.
  *Done when:* editing `src/server/index.ts` several times in dev still logs `database updated` only once per minute.

### Client

- [ ] **P1-11 Delete may never reach the server.**
  In [src/pages/watch-sidebar.tsx](src/pages/watch-sidebar.tsx) (line ~55), `location.href = "/"` runs before `await deleteVideo(...)`. Navigating away can cancel the request.
  *Fix:* await the delete first, then `navigate("/")`. Add a `confirm()` before deleting, because this removes the folder from disk.

- [ ] **P1-12 Count and tag updates race with the data reload.**
  The buttons in `watch-sidebar.tsx` and `tag.tsx` are `type="submit"` inside the `<Form>` in [src/components/content.tsx](src/components/content.tsx). Clicking one fires the `fetch` and submits the form (which reloads the route data) at the same time, so the reload can return the old value.
  *Fix:* use React Router `action`s with `useFetcher` (or `fetcher.submit`) so data reloads after the change finishes. Make the non-form buttons `type="button"`.
  *Done when:* clicking +1 quickly several times always shows the correct count.

- [ ] **P1-13 Search terms are not URL-encoded.**
  `navigate(`/search/${search}`)` in [src/components/header.tsx](src/components/header.tsx) and the tag click in [src/components/tag.tsx](src/components/tag.tsx) break on `?`, `#`, `/` and `%`.
  *Fix:* use `encodeURIComponent`. The cleaner fix is to move search to a query string (see P2-04).

- [ ] **P1-14 Using array indexes as list keys shows wrong tag values.**
  Tags and gallery items use `key={index}`. `Tag` uses an uncontrolled `defaultValue`, so deleting a tag can leave the wrong text in the remaining inputs.
  *Fix:* key tags by `tag` and videos by `video.id`. The "add tag" flow (`TagAdder` adds `""`, then `onBlur` removes `""` and adds the new value) is fragile and allows multiple empty tags. Replace it with a local input that only calls `addTag` once a value is entered.
